# ADR-0006：移除归档、版本撤回与所有权转移

- 状态：已接受
- 日期：2026-07-29

## 背景

“我发布的 Skill”需要保持清晰、可预测的维护流程。归档与恢复、版本撤回、所有权转移分别引入额外的生命周期、版本状态和邀请状态机，但当前产品并不需要这些中间状态。

产品已经提供永久删除，并确认 Owner 只维护自己最初发布的 Skill。因此继续保留上述入口和写接口会增加理解成本，也会让浏览页、管理页和服务端权限出现不必要的分支。

## 决策

- 不提供 Skill 归档或恢复；需要移除线上 Skill 时，Owner 使用现有的永久删除功能。
- 不提供版本撤回；已经发布的版本保持不可变，并永久保留在版本历史中。
- 不提供所有权转移；首个版本上传者是固定 Owner。
- “我发布的 Skill”详情中的管理操作只保留“上传新版本”和“编辑展示信息”，永久删除保留在列表页现有入口。
- 删除归档、恢复、版本撤回和所有权转移对应的前端入口、应用接口、Mock 写操作与 OpenAPI 写接口。
- 已存在的 `ARCHIVED` Skill 和 `WITHDRAWN` 版本只作为历史数据兼容读取，不再允许客户端创建新的此类状态；数据库字段和枚举可在后续数据迁移中单独清理。

## 结果

### 正面影响

- Owner 的维护路径更短，管理页不再出现当前产品不需要的状态机。
- 已发布版本的含义稳定，不会因撤回而改变当前版本。
- Owner 身份不会在不同用户间变化，权限判断更直接。
- 客户端、Mock 和服务端契约采用同一组可执行能力。

### 代价

- 永久删除没有恢复入口，确认文案必须清楚说明影响。
- Owner 停用后，该 Skill 不能继续发布新版本；如需继续维护，应以新的 Skill 重新发布。
- 历史状态字段在完成数据迁移前仍需保留只读兼容。
