# ADR-0004：Skill 所有权、版本线与派生关系

- 状态：部分被 ADR-0005、ADR-0006 取代
- 日期：2026-07-17

> ADR-0005 已取代“任何登录用户可以直接发布版本”的决定。当前规则改为只有 Owner 可以直接发布新版本，非 Owner 的候选版本审核流程另行设计。
>
> ADR-0006 已取代归档、恢复、版本撤回和所有权转移相关决定。Owner 固定为首个版本上传者，已发布版本不可撤回，Skill 只提供永久删除。

## 背景

平台最初允许任何登录用户直接更新 Skill，同时需要明确当前管理责任、永久贡献归属、并发发布、历史版本分化和离职账号处理。开放更新规则后来被 ADR-0005 取代；Owner、版本上传者和协作者仍需保持不同含义。

## 决策

- Skill 保存当前 `owner`；首个版本上传者成为初始 Owner，原始创建者从 `1.0.0` 的 `uploadedBy` 推导。
- 协作者由成功发布过版本的用户聚合，是永久贡献记录；未发布版本的历任 Owner 不算协作者。
- 版本发布权限以 ADR-0005 为准：只有当前 Owner 可以直接发布新版本。
- 版本不可变，使用 `baseVersionId` 检查并发；内容哈希必须与全部历史版本不同。
- 新 Skill 与派生 Skill 从 `1.0.0` 开始；所有已发布版本均不可撤回。
- 从历史版本独立发展时创建新 `skillName` 的派生 Skill，并保存直接来源 Skill 与版本。
- 允许多级派生，不提供自动回流或合并功能。
- Owner 固定为首个版本上传者，不提供所有权转移。
- 不提供归档与恢复；Owner 可以通过明确确认的永久删除流程移除 Skill。

## 结果

### 正面影响

- 当前管理责任、历史贡献和每个版本的实际发布者可以分别表达。
- 开放更新不会牺牲审计和并发安全。
- 不同需求使用独立 Skill，避免把同一名称变成难以解释的分支图。
- 停用账号不会删除历史；需要继续维护时以新的 Skill 重新发布。

### 代价

- 需要版本来源和派生来源等额外模型。
- 客户端需要展示 Owner、协作者、版本上传者和来源链的不同含义。
- 平台只能提示派生 Skill 的触发重叠，不能可靠判断手工复制后的语义来源。

## 后续约束

- 任何权限判断都使用当前 Owner、协作者聚合和管理员配置，不能使用含义不清的“创建者权限”。
- 版本号必须高于全部历史版本。
- 已发布版本不可变，不能通过状态操作改变当前版本。
- 原 Skill 的生命周期变化不能级联修改派生 Skill。
