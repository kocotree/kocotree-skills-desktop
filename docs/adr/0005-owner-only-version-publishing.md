# ADR-0005：仅 Owner 可以直接发布新版本

- 状态：已接受
- 日期：2026-07-29

## 背景

ADR-0004 曾允许任何登录用户直接更新现有 Skill，并在成功发布后成为协作者。该规则会让非 Owner 无需确认即可改变线上最新版本。即使客户端隐藏发布入口，旧客户端、脚本或直接 HTTP 请求仍然可以绕过界面调用发布接口。

Skill 浏览与 Skill 管理也承担不同职责：浏览页用于查看和安装，管理页用于维护自己发布的 Skill。把两类操作放在同一详情入口会模糊权限边界。

## 决策

- 只有当前 Owner 可以直接给现有 Skill 发布新版本。
- 非 Owner 不能通过客户端或直接接口把候选内容变成线上最新版本。
- Skill 浏览页的详情只提供查看、历史版本浏览和安装，不显示上传新版本或编辑展示信息等管理操作。
- 管理操作只在“我发布的 Skill”进入的详情中显示，并继续由服务端校验 Owner 身份；隐藏按钮不视为权限控制。
- 按 ADR-0006，系统不提供所有权转移、归档、恢复和版本撤回。
- 如果未来允许其他用户贡献，应新增“提交候选版本 → Owner 审核 → 正式发布”的独立流程，候选版本在批准前不得影响线上版本。
- 当前真实后端尚未建立独立 Owner 字段和转移模型，在过渡期内以 `createdBy` 作为当前 Owner；所有权模型落地后必须改为校验真实 Owner。

## 结果

### 正面影响

- Owner 可以控制线上最新版本，避免其他登录用户直接覆盖。
- 浏览和管理入口职责清晰，普通用户不会看到无权执行的操作。
- 服务端权限与客户端呈现采用同一规则，旧客户端和直接请求也不能绕过。

### 代价

- 原来的开放更新能力被取消。
- 非 Owner 暂时没有贡献现有 Skill 的入口；候选版本审核需要后续单独设计。
- `createdBy` 只是过渡期 Owner，需要在所有权模型完成后迁移。

## 被取代的决定

- ADR-0004 中“任何登录用户可以发布版本，成功后成为协作者”的决定。
- `INTERVIEW_DECISIONS.md` 中“非 Owner 可以直接更新 Skill”的决定。
